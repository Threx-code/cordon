# Code of conduct

## The short version

Be someone other people can work with. Disagree about the code, not about each
other. If you are about to write something you would not say to a colleague's
face in an office, write a different thing.

## Why this file is short

A code of conduct is read twice: once by somebody deciding whether to open an
issue, and once by somebody deciding whether to report behaviour. Both readings
want the same two answers -- what is not acceptable, and who to tell -- and a
long document buries them.

```
   ┌──────────────────────────────────────────────────────────────────────┐
   │  SOMETHING HAPPENED                                                  │
   │                                                                      │
   │   in a public issue,  ──►  report it  ──►  security@threx.dev        │
   │   PR or discussion                         (or any maintainer, by    │
   │                                             private message)         │
   │                                                                      │
   │   involving a         ──►  report it  ──►  any OTHER maintainer      │
   │   maintainer                                                         │
   │                                                                      │
   │  Every report is read. You will get an answer, and you will be told  │
   │  what happened as a result, unless telling you would identify        │
   │  somebody who asked not to be identified.                            │
   └──────────────────────────────────────────────────────────────────────┘
```

## Not acceptable

- Harassment, whether public or private. This includes sustained disruption of
  a discussion after being asked to stop.
- Personal attacks. "This design is wrong because X" is a technical argument.
  "You are an idiot for designing this" is not, whatever X is.
- Discriminatory language or imagery, including as a joke. Intent is not the
  test; whether it lands that way is.
- Publishing somebody's private information without their explicit permission.
- Sexual attention or advances of any kind in project spaces.

## Expected

- Assume the other person read the code and reached a different conclusion,
  rather than that they did not read it.
- Accept that a maintainer may say no. A project that merges everything is a
  project with no design.
- When you are wrong, say so plainly and move on. Nobody needs the ceremony.

## Scope

Anywhere the project happens: issues, pull requests, discussions, commit
messages, review comments, and any space where somebody is representing the
project.

## Enforcement

Maintainers will remove, edit or reject contributions that do not follow this
document, and will explain why when they do. Repeated or severe behaviour
results in a ban from project spaces.

Reports go to **security@threx.dev**. If the report is about a maintainer, send
it to a different maintainer -- their contact details are on their GitHub
profile. A report will not be disclosed to the person it is about without the
reporter's agreement, and no action is taken against a reporter for reporting.
