# Real executables and the module values the reference engine gives them

`expected.json` is the reference engine's own `pe`, `elf` and `dotnet` module data for each file
(`modules_callback`), and the results of the module functions it lists (`console.log`), recorded
once; `test_builtin.py` holds Cordon's engine to them. Every file is legitimate,
redistributable software, taken unchanged from a public npm package:

| file | is | licence | from |
|---|---|---|---|
| `cpython-wmi.pyd` | CPython's `_wmi` extension (signed, countersigned; resources, Rich header, PDB path, exports, delay-load imports) | PSF License 2.0 | `@backtomyfuture/exchange-cli-win32-x64` 0.2.11 |
| `amazon-lambda-core.dll` | AWS Lambda .NET core library (signed, countersigned, .NET metadata) | Apache License 2.0 | `@sstlv/sst` 2.26.6 |
| `system-runtime-compilerservices-unsafe.dll` | .NET `System.Runtime.CompilerServices.Unsafe` (signed, .NET metadata) | MIT | `@sstlv/sst` 2.26.6 |
| `libffi-raw_api.o` | libffi's `raw_api.c`, compiled (ELF symbols: `telfhash`, `import_md5`) | MIT | `@jpruden/ffi-napi` 2.4.6 |

`functions.json` pins module-function outputs for an exact-equality check (not kind checks), covering more
than `expected.json`'s recorded set: per file it holds the 33 varied calls the function differential uses
(absent names, out-of-range RVAs, ordinal/regex/delayed forms) plus per-file "hitting" arguments — a real
imported dll/function, a real export, a real section name, an in-section RVA — and `libffi-raw_api.o` stands
in as a file where every `pe.*` call is undefined (no output). Each entry is `{calls, logs}`: the
`console.log` calls and the reference's sorted output. It is generated by the function differential in
`scripts/reference/` — one step picks the per-file hitting arguments with our reader, another runs both
engines, and the reference's output is recorded only after it is confirmed identical to ours.
`test_pe.py` replays every call through our engine and asserts equality.

`malformed.json` holds the reference engine's `pe`/`elf`/`dotnet` trees for a malformed set derived from
the four benign files above, so the readers are proven on broken input too without shipping a malware
corpus. The bytes are not stored: `tests/conformance/generate/binary_modules.py` regenerates them
deterministically (pinned seed `cordon-binary-malformed-v1`) — per file, truncations at a spread of
boundary fractions, bit-flips in the header region, field overwrites with extreme values, and a scatter of
random bytes — giving the same 75 variants from the committed fixtures on any machine. Each entry records
the variant's SHA-256, so `test_malformed_replay.py` fails loudly if the mutator ever drifts from what
was recorded. The malformed set carries the same licences as the benign files it is derived from. Our
readers match the reference on every leaf of all 75 variants, so there is no divergence to allow for. The
values were recorded once with `scripts/reference/record_binary_modules.py`; regenerating and replaying
need neither the reference nor any corpus.

Which reference these values were recorded with, and how to re-record them, is in
`scripts/reference/README.md`: the tools that need it live there, apart from Cordon.
